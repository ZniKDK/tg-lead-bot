# Telegram-бот для записи клиентов

Бот принимает заявки на услуги: клиент выбирает услугу, день и свободное время, оставляет имя и телефон. Администратор сразу получает карточку заявки и меняет её статус одной кнопкой. Все заявки хранятся в базе, их можно выгрузить в Excel.

Подходит для салонов, автосервисов, мастерских, репетиторов, клиник — везде, где клиенты записываются на время.

## Возможности

**Для клиента**
- запись в пару нажатий: услуга → дата → время → имя → телефон;
- показывается только свободное время: занятые и прошедшие слоты скрыты;
- бот отвечает на любое сообщение и подсказывает, что делать дальше;
- телефон можно отправить кнопкой или ввести вручную — номер проверяется и приводится к виду `+7XXXXXXXXXX`;
- кнопка «Назад» на каждом шаге, `/cancel` — отменить запись.

**Для администратора**
- мгновенное уведомление о новой заявке с кнопками «Выполнена» / «Отменить»;
- `/leads` — последние 10 заявок, `/new` — необработанные;
- `/export` — все заявки в CSV-файле, который сразу открывается в Excel;
- при запуске бот присылает админам сообщение «Бот запущен» — так сразу видно, что уведомления доходят;
- отменённая заявка освобождает время для других клиентов.

**Надёжность**
- одно время нельзя занять дважды: защита на уровне базы данных, даже если два клиента нажали кнопку одновременно;
- если уведомление админу не дошло, заявка всё равно сохраняется;
- услуги, рабочие часы, длина слота и выходные настраиваются в `.env` без правки кода.

## Стек

Python 3.11+ · aiogram 3 · SQLite (aiosqlite) · pytest · Docker

## Быстрый старт

1. Создайте бота у [@BotFather](https://t.me/BotFather) и получите токен.
2. Узнайте свой Telegram ID у [@userinfobot](https://t.me/userinfobot).
3. Установите и запустите (Windows, PowerShell):

```powershell
git clone https://github.com/ZniKDK/tg-lead-bot.git
cd tg-lead-bot
python -m venv .venv
.venv\Scripts\activate
pip install -r requirements.txt
copy .env.example .env   # впишите BOT_TOKEN и ADMIN_IDS
python -m bot.main
```

На Linux вместо `.venv\Scripts\activate` — `source .venv/bin/activate`, вместо `copy` — `cp`.

### Запуск на сервере через Docker

```bash
cp .env.example .env   # заполните
docker compose up -d --build
```

База лежит в папке `data/` на хосте и не теряется при перезапуске контейнера. Бот перезапускается сам после сбоя или перезагрузки сервера.

## Настройки (`.env`)

| Переменная | Что задаёт | Пример |
|---|---|---|
| `BOT_TOKEN` | токен бота | `123456:ABC...` |
| `ADMIN_IDS` | ID администраторов через запятую, обязательно. Каждый админ должен один раз нажать /start в боте | `111111111,222222222` |
| `SERVICES` | список услуг через `;` | `Стрижка;Окрашивание;Укладка` |
| `WORK_START`, `WORK_END` | рабочие часы | `10:00`, `19:00` |
| `SLOT_MINUTES` | длина одного слота, минут | `60` |
| `DAYS_AHEAD` | на сколько дней вперёд открыта запись | `7` |
| `DAYS_OFF` | выходные (0 — пн, 6 — вс) | `5,6` |
| `DB_PATH` | путь к базе | `data/leads.db` |

## Структура

```
bot/
├── main.py          # запуск, подключение роутеров
├── config.py        # чтение настроек из .env
├── db.py            # работа с SQLite
├── utils.py         # телефон, свободные слоты, CSV — без Telegram, легко тестировать
├── keyboards.py     # кнопки
├── texts.py         # все тексты сообщений в одном месте
└── handlers/
    ├── client.py    # сценарий записи (FSM)
    └── admin.py     # команды администратора
tests/               # 28 тестов: настройки, утилиты, база, сквозной сценарий
```

## Тесты

```powershell
pip install -r requirements-dev.txt
pytest
```

Сквозные тесты (`tests/test_flow.py`) проходят весь диалог клиента и действия администратора без настоящего Telegram: запросы к API перехватывает фейковая сессия.

## Что можно доработать под заказчика

- напоминание клиенту за день или за час до визита;
- выбор мастера или филиала;
- выгрузка заявок в Google Таблицы или CRM (amoCRM, Битрикс24);
- онлайн-оплата предоплаты через ЮKassa;
- веб-админка вместо команд в чате.
